# 音声入力の公開前確認（追加の有料APIなし）

今回の変更はApple標準Speech、端末内の文字処理だけを使用する。有料の文字起こしAPI、外部AI、サーバー契約は追加しない。Apple Speechが端末内で処理することを強制する変更は行っていない。ネットワーク利用の有無はApple側の対応・環境による。

## 検証状況

Nodeのテストで日時の言い直し、複数通知、録音の待ち時間、古い録音イベントの排除、認識候補の配分を検証する。既存81例と日時・辞書等のテストも実行する。

このクラウド環境にはXcodeとiPhoneのマイクがない。Swiftのビルド、実際の音声認識精度、音量しきい値の妥当性は未確認。文字テストの成功を「音声精度が上がった割合」として扱わない。

## 実機での比較方法

1. 旧版と新版で同じ端末・マイク・距離・部屋を使う。Koeは削除せず上書き更新する。ローカル保存データは事前にバックアップする。
2. Googleの予定を変更しない「お試し表示」で確認画面まで進める。実データへの登録は不要。
3. 下の各文を同じペースで3回ずつ読む。旧版が手元にない場合は新版の評価のみとし、改善率を算出しない。
4. 一文の途中に2秒の間を置く試験、静かな場所、生活音のある場所、端末内蔵マイク・使用予定のイヤホンを分ける。
5. 「聞こえた文字が正しいか」「予定の日時・内容・場所・通知がすべて正しいか」「途中で切れたか」「終了までの待ち時間」を記録する。
6. iPhone・iPad・Macそれぞれで、連続録音、途中キャンセル後の再録音、停止ボタン、マイク拒否・通信切断を試す。

| 読み上げ文 | 確認する点 |
| --- | --- |
| 明日20時から21時半まで勉強会 | 同日20:00–21:30、1時間30分 |
| 明日20時、いや21時から会議 | 開始21:00、予定名に「いや」が残らない |
| 明日、いや明後日20時会議 | 明後日20:00 |
| 明日20時会議、30分前と10分前に通知 | 通知2件、予定名は「会議」 |
| 明日20時会議、通知は1時間前と10分前 | 通知60分前と10分前 |
| 明日20時会議、30分前に通知、10分前に通知 | 通知2件 |
| 明日23時から翌日1時まで夜勤 | 日をまたぐ日時と2時間の長さを確認 |
| 来週金曜14時、本館3階会議室で打ち合わせ | 日付・場所・予定名 |
| 11月5日13時30分から14時30分、週次スタッフ会議、新館3階大会議室 | 長い文、施設名、途中で切れないこと |
| 毎週月曜9時に朝会、10分前に通知 | 繰り返しと通知 |
| いやま医院で明日10時に検診 | 名前を言い直し扱いにしない |
| 明日14時、（2秒待つ）会議、（2秒待つ）10分前に通知 | 途中の間で切れないこと |

## リリース判断

- 意図と違う日時・通知が確認画面に出た場合は記録し、修正するまでその例を合格にしない。
- 環境音で自動停止しない／声が小さく早く止まる場合は、まず待ち時間5秒・8秒・自動停止なしも比較する。
- OSが先に認識を終了する場合があるため、「自動停止なし」は無制限録音を保証しない。
- 初期の音量しきい値はRMS 0.01。実機確認後に変更の要否を判断する。
- 曖昧な人名や自由な言い直しを推測で置換しない。現在自動処理する言い直しは、明示された数値の時刻と相対日付に限定する。
